# 🚀 ربات فروش ممبر + دو مینی‌اپ

ربات فروش ممبر (سورس اصلی) با دو **مینی‌اپ کاملا جدا از هم** روی همان ربات:

| مینی‌اپ | آدرس | تم گرافیکی | چه می‌فروشد |
|---|---|---|---|
| 🌟 **خدمات تلگرام** | `?app=tg` | شفق قطبی — بنفش/فیروزه‌ای، شیشه‌ای، ستاره‌های متحرک | استارز، پریمیوم، گیفت، تون، ترون |
| 🛡 **فروش کانفیگ** | `?app=cfg` | سایبر گرید — مشکی/نئون، شبکه پرسپکتیو، فونت مونو | سرویس حجمی، نامحدود، آی‌پی اختصاصی |

دکمه هر دو مینی‌اپ **دقیقا زیر دکمه‌های ثبت سفارش محصولات** می‌نشیند (و بالای دکمه «لیست تعرفه‌ها»).

## فایل‌ها

```
bot_master_membership.php   ربات اصلی (وبهوک) — سورس فروش ممبر + قلاب‌های مینی‌اپ
miniapps.php                منطق مینی‌اپ‌ها: پیکربندی، API، سفارش، پرداخت، پنل مدیریت
miniapp_view_tg.php         ظاهر مینی‌اپ خدمات تلگرام
miniapp_view_cfg.php        ظاهر مینی‌اپ فروش کانفیگ
health.php                  تشخیص مشکلات راه‌اندازی (اختیاری — بعد از رفع مشکل پاکش کنید)
```

هر چهار فایل باید کنار هم در یک پوشه باشند. نیازی به دیتابیس یا کتابخانه بیرونی نیست.
داده‌ها در `data_master/` به صورت JSON ذخیره می‌شوند.

> ⚠️ **نیازمندی: PHP 8.0 یا بالاتر** (به‌همراه `curl`، `json` و `mbstring`).
> روی PHP 7.4 کد اصلا اجرا نمی‌شود و ربات بی‌صدا هیچ جوابی نمی‌دهد.
> برای بررسی، `health.php` را کنار فایل‌ها آپلود و باز کنید.

## راه‌اندازی

۱. هر چهار فایل را روی هاست آپلود کنید و مطمئن شوید وب‌سرور اجازه نوشتن در پوشه را دارد.

۲. وبهوک را ست کنید:

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://DOMAIN/bot_master_membership.php
```

۳. داخل ربات `/panel` را بزنید → **🚀 مینی اپ‌ها** → **🔗 آدرس عمومی** و آدرس کامل همین فایل را بفرستید:

```
https://DOMAIN/bot_master_membership.php
```

> ⚠️ آدرس حتما باید **https** باشد — تلگرام مینی‌اپ روی http را باز نمی‌کند.
> تا وقتی این آدرس ثبت نشود، دکمه مینی‌اپ‌ها اصلا نمایش داده نمی‌شود.

۴. تمام. `/start` → «خرید محصول» → دکمه‌های مینی‌اپ زیر محصولات دیده می‌شوند.

## پنل مدیریت — `/panel` ← 🚀 مینی اپ‌ها

برای **هر مینی‌اپ جداگانه**:

- **🎨 دکمه زیر محصولات** — متن، ایموجی، **رنگ** (آبی/سبز/قرمز)، ایموجی پریمیوم، ترتیب نمایش
- **🖌 تم و رنگ گرافیکی** — رنگ اصلی، رنگ دوم، رنگ تاکید، پس‌زمینه (`#RRGGBB`)، درخشش، بافت
  - **🎭 پالت‌های آماده**: بنفش کهکشانی، نئون سایبری، غروب آتشین، اقیانوس عمیق، طلایی رویال، قرمز خونی، مینت یخی، سفید مینیمال
- **✏️ متن‌های مینی‌اپ** — عنوان، زیرعنوان، شعار، یادداشت فاکتور، واحد پول و متن تک‌تک دکمه‌های داخل اپ
- **💠 متن و رنگ دکمه‌های شیشه‌ای** — دکمه‌های فاکتور داخل ربات (پرداخت کیف پول، کارت به کارت، ارسال رسید، انصراف، باز کردن مینی‌اپ): متن، ایموجی، **رنگ** و ایموجی پریمیوم هرکدام جدا
- **📂 دسته‌ها** — همان تب‌های بالای مینی‌اپ (افزودن، نام، ایموجی، خاموش/روشن، حذف)
- **🛒 سرویس‌ها** — نام، ایموجی، قیمت، توضیح، برچسب، دسته، ترتیب، خاموش/روشن، حذف
  - **❓ نوع سوال**: بدون سوال · آیدی تلگرام · تعداد (قیمت × تعداد با حداقل/حداکثر) · آدرس ولت · توضیح دلخواه
- **🧪 پیش‌نمایش** — دکمه واقعی مینی‌اپ برای تست
- **🧾 سفارش‌ها** — سفارش‌های در انتظار تایید و آماده تحویل

تنظیمات دو مینی‌اپ کاملا از هم جدا نگهداری می‌شود؛ تغییر یکی روی دیگری اثری ندارد.

## 🔌 قیمت‌گذاری زنده — `/panel` ← 🚀 مینی اپ‌ها ← 🔌 قیمت‌گذاری زنده

قیمت‌ها می‌توانند به‌جای عدد ثابت، از منبع زنده گرفته شوند:

| منبع | چه چیزی را قیمت می‌دهد | تنظیم |
|---|---|---|
| 🎁 مارکت گیفت | گیفت‌هایی که «کلید مارکت» دارند | آدرس API + مسیر فیلدها + درصد سود |
| ⭐️ نرخ استارز | همه بسته‌های استارز و گیفت‌های استارزی | قیمت هر ۱ استارز |
| 💱 نرخ ارز | تون و ترون | آدرس نرخ (پیش‌فرض نوبیتکس) + درصد سود |

هر سرویسی که منبع زنده نداشته باشد با همان قیمت دستی خودش فروخته می‌شود، پس
خاموش بودن این بخش هیچ‌چیز را خراب نمی‌کند.

### وصل کردن به مارکت گیفت

چون هر مارکت (Tonnel، Portals، …) ساختار پاسخ خودش را دارد، آدرس و اسم فیلدها
دستی تنظیم می‌شود — هیچ آدرسی از پیش حدس زده نشده:

1. **🔗 آدرس API** را بدهید.
2. **🔌 تست اتصال** را بزنید — پاسخ خام و کلیدهایش نمایش داده می‌شود.
3. از روی همان، **مسیر فهرست** (مثلا `data.results`)، **فیلد نام** و **فیلد قیمت** را پر کنید.
4. دوباره تست بزنید — حالا فهرست گیفت‌ها با شناسه‌شان نشان داده می‌شود.
5. همان شناسه‌ها را در هر گیفت، در **🔗 کلید مارکت** بگذارید.

قیمت مارکت × نرخ ارز مبدا × (۱ + درصد سود) = قیمت نهایی، و به عدد دلخواه شما گرد می‌شود.
اگر مارکت از دسترس خارج شود، آخرین قیمت کش‌شده استفاده می‌شود و اگر آن هم نبود،
قیمت دستی — یعنی فروشگاه هیچ‌وقت با قیمت صفر یا غلط نمی‌فروشد.

## 🛡 امنیت

- **قیمت هرگز از سمت کاربر خوانده نمی‌شود** — همیشه روی سرور و از روی پیکربندی حساب می‌شود.
  هر عددی که در درخواست بفرستند نادیده گرفته می‌شود.
- **اعتبارسنجی `initData`** با `HMAC-SHA256` و توکن ربات؛ امضای دستکاری‌شده، جعل آیدی
  و داده قدیمی‌تر از **۱ ساعت** رد می‌شوند.
- **محدودیت نرخ** سه‌لایه: ۹۰ درخواست در دقیقه برای هر IP، ۴۰ برای هر کاربر،
  و **۶ سفارش در دقیقه** برای هر کاربر.
- **ضد بازپخش**: با یک `initData` حداکثر ۱۵ سفارش — خرید عادی آزاد است ولی
  کسی نمی‌تواند با یک نشست شنودشده صدها سفارش بسازد.
- **ضد سفارش تکراری**: همان سفارش در ۴۵ ثانیه دوبار ثبت نمی‌شود (دابل‌کلیک یا اسکریپت).
- **محافظ تغییر قیمت**: اگر نرخ زنده بین باز شدن مینی‌اپ و زدن دکمه عوض شود،
  فاکتور با قیمت قدیمی صادر نمی‌شود؛ قیمت تازه نشان داده می‌شود.
- **هدرهای امنیتی**: CSP سخت‌گیرانه (`default-src 'none'`)، `frame-ancestors` فقط تلگرام،
  `nosniff`، `no-referrer`، و بستن دسترسی به دوربین/میکروفن/موقعیت.
- **ورودی‌ها**: فقط POST، سقف ۳۲ کیلوبایت بدنه، آیدی تلگرام با الگوی سخت‌گیرانه،
  تعداد فقط عدد صحیح متناهی، و برش هر متن به ۳۰۰ کاراکتر.
- **عضویت اجباری و مسدودی کاربر** روی سفارش‌های مینی‌اپ هم اعمال می‌شود.
- تایید، رد و تحویل سفارش فقط برای ادمین.

> هیچ سیستمی «غیرقابل نفوذ» نیست. موارد بالا سطح حمله را تا حد زیادی می‌بندند،
> ولی سه چیز بیرون از کد است و به عهده شماست: **HTTPS سالم**، **توکن ربات را
> جایی منتشر نکنید**، و **دسترسی فایل‌های `data_master` را ببندید**.

## ⚡️ سرعت

هر دو مینی‌اپ برای وب‌ویو موبایل بهینه شده‌اند: لیست فقط یک بار ساخته می‌شود و
جستجو/فیلتر بدون بازسازی DOM اعمال می‌شود، پس‌زمینه‌ها بدون `filter: blur` و
بدون انیمیشن پرهزینه‌اند، و انیمیشن ورود کارت‌ها فقط بار اول اجرا می‌شود.

اگر باز هم روی گوشی‌های ضعیف کند بود: `/panel` ← 🚀 مینی اپ‌ها ← اپ موردنظر ←
🖌 تم و رنگ ← **⚡️ سطح افکت** را روی «سبک» یا «خاموش» بگذارید.

## مسیر سفارش

```
کاربر در مینی‌اپ سرویس را می‌زند
        ↓
سرور initData تلگرام را با HMAC بررسی می‌کند (جعل‌ناپذیر) و قیمت را خودش حساب می‌کند
        ↓
فاکتور داخل ربات فرستاده می‌شود
        ↓
💰 پرداخت از کیف پول            💳 کارت به کارت
   (اگر موجودی کافی باشد)          → ارسال رسید → تایید ادمین
        ↓                                ↓
        └────────── سفارش «پرداخت‌شده» ──────────┘
                          ↓
        ادمین با «📤 تحویل سفارش» کانفیگ/کد/لینک را می‌فرستد
                          ↓
              همان محتوا برای کاربر ارسال و سفارش بسته می‌شود
```

فاکتور هر کاربر فقط با همان کاربر پرداخت می‌شود و پرداخت دوباره روی یک فاکتور
جلوگیری می‌شود. بقیه موارد امنیتی در بخش «🛡 امنیت» بالا آمده است.

