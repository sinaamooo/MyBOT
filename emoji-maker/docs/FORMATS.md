# فرمت‌های خروجی و محدودیت‌های تلگرام

همه‌ی خروجی‌ها قبل از تحویل با محدودیت‌های رسمی تلگرام
(<https://core.telegram.org/stickers>) سنجیده می‌شوند و نتیجه (معتبر / هشدار / نامعتبر)
با توضیح فارسی کنار هر فایل نمایش داده می‌شود.

## ۱. ایموجی ویدیویی — WEBM

| مورد | مقدار تلگرام | پیاده‌سازی در این پروژه |
|---|---|---|
| ابعاد | دقیقاً ۱۰۰×۱۰۰ پیکسل | فریم‌ها مستقیم در ۱۰۰×۱۰۰ رندر می‌شوند |
| کدک | VP9 داخل WEBM | `libvpx-vp9`، `yuva420p` (شفافیت واقعی) |
| مدت | حداکثر ۳ ثانیه | مدت انیمیشن حداکثر ۳ ثانیه بریده/تنظیم می‌شود |
| نرخ فریم | حداکثر ۳۰ | ۳۰ فریم بر ثانیه (یا کمتر) |
| حجم | حداکثر ۲۵۶ کیلوبایت | کیفیت (CRF) مرحله‌به‌مرحله پایین می‌آید تا حجم جا شود |
| صدا | نباید وجود داشته باشد | `-an` (بدون صدا) |
| حلقه | — | انیمیشن‌ها بی‌درز تکرار می‌شوند (فریم اول و آخر یکسان) |

نیازمند **FFmpeg با کدک libvpx-vp9** و اجازه‌ی `proc_open` در PHP است. اگر روی هاست
در دسترس نباشد، ربات به‌طور خودکار فقط TGS و PNG را پیشنهاد می‌دهد.
اعتبارسنجی WEBM بدون نیاز به ابزار خارجی (خواندن مستقیم EBML: ابعاد، کدک، مدت، آلفا) و
در صورت وجود `ffprobe` با دقت بیشتر انجام می‌شود.

## ۲. ایموجی متحرک برداری — TGS (Lottie)

| مورد | مقدار تلگرام | پیاده‌سازی |
|---|---|---|
| فرمت | JSON لاتی فشرده با gzip | `gzencode` سطح ۹ |
| بوم | ۵۱۲×۵۱۲ | ثابت ۵۱۲ |
| نرخ فریم | ۶۰ | ۶۰ (قالب‌های اصلی هرچه بوده حفظ می‌شود) |
| مدت | حداکثر ۳ ثانیه | حداکثر ۱۸۰ فریم |
| حجم | حداکثر ۶۴ کیلوبایت | کاهش کلیدفریم‌ها، گرد کردن اعداد، ساده‌سازی لوگوی ردیابی‌شده |
| ممنوعه‌ها | عکس، ماسک، افکت لایه، 3D، Expression، Repeater، Merge Path، Star، … | در خروجی‌های طراحی‌شده استفاده نمی‌شوند |

برای قالب‌های آماده (که از ایموجی‌های اصلی تلگرام ساخته شده‌اند) ویژگی‌هایی مثل
Gradient Stroke یا Merge Path که در فایل اصلی بوده و تلگرام قبلاً پذیرفته، به‌جای خطا
«هشدار» گزارش می‌شوند.

TGS کاملاً با PHP ساخته می‌شود (بدون FFmpeg) و روی هر هاستی کار می‌کند. لوگوی تصویری برای
TGS به مسیرهای برداری تبدیل می‌شود (ردیابی رنگ‌ها)، چون TGS نمی‌تواند عکس داشته باشد.

## ۳. ایموجی ثابت — PNG

۱۰۰×۱۰۰ پیکسل با پس‌زمینه‌ی شفاف، حداکثر ۵۱۲ کیلوبایت.

## ۴. انتشار پک

* نوع پک: `custom_emoji`، نام پک باید به `_by_<نام‌کاربری ربات>` ختم شود (ربات خودش می‌سازد).
* ساخت پک با ۱ تا ۵۰ ایموجی اول (`createNewStickerSet`) و افزودن بقیه با `addStickerToSet`
  تا سقف ۲۰۰ ایموجی.
* هر ایموجی ۱ تا ۲۰ ایموجی متنی مرتبط دارد (پیش‌فرض ⭐، قابل تغییر).
* گزینه‌ی `needs_repainting` برای ایموجی‌های تک‌رنگ که باید با رنگ متن کاربر رنگ بگیرند.
* بعد از انتشار، لینک `https://t.me/addemoji/<name>` برای کاربر ارسال می‌شود.

## ۵. پیش‌نمایش‌ها

* پیش‌نمایش متحرک MP4 (با FFmpeg) یا GIF (کاملاً PHP، وقتی FFmpeg نیست).
* برای پک‌های چندتایی یک «شبکه‌ی متحرک» شماره‌دار (و تصویر ثابت فهرست) ساخته می‌شود تا
  کاربر موارد دلخواه را انتخاب کند.
* خروجی‌ها همیشه در یک فایل ZIP همراه `manifest.json` (برچسب، فرمت، نتیجه‌ی اعتبارسنجی) تحویل
  داده می‌شوند.
