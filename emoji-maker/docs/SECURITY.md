# امنیت

| خطر | راهکار پیاده‌شده |
|---|---|
| لو رفتن توکن ربات | توکن فقط در `.env` (بیرون از ریشه‌ی وب) یا در تنظیمات رمزنگاری‌شده‌ی دیتابیس (libsodium / AES-256-GCM با `APP_KEY`)؛ هیچ‌جا در سورس، لاگ یا پاسخ‌ها نمایش داده نمی‌شود؛ `Redactor` همه‌ی لاگ‌ها را پاک‌سازی می‌کند (توکن، رمزها، کلیدها، آدرس‌های حاوی توکن). |
| درخواست جعلی به وبهوک | سرآیند `X-Telegram-Bot-Api-Secret-Token` با مقایسه‌ی زمان‌ثابت (`hash_equals`) بررسی می‌شود؛ محدودیت حجم بدنه، نوع محتوا، جلوگیری از پردازش تکراری با `update_id`؛ بررسی اختیاری IP‌های تلگرام. |
| Path Traversal | مسیر هیچ فایلی از ورودی کاربر ساخته نمی‌شود؛ فایل‌ها نام تصادفی در دسته‌های مشخص `storage` دارند و `Storage::path()` هر مسیر را با `realpath` داخل ریشه‌ی ذخیره‌ساز محدود می‌کند؛ فایل ZIP قالب‌ها بدون استخراج روی دیسک و با رد نام‌های `..`/مطلق خوانده می‌شود. |
| دسترسی مستقیم به فایل‌های خصوصی | `storage` بیرون از `public` (یا با `.htaccess`/قانون nginx مسدود)؛ دانلود فقط با لینک امضاشده‌ی HMAC و زمان‌دار (`download.php`) که مالک فایل را هم بررسی می‌کند. |
| تزریق فرمان | ابزار خارجی (FFmpeg) فقط با `proc_open` و آرایه‌ی آرگومان (بدون shell)، با محدودیت زمان و `nice`. |
| SQL Injection | همه‌ی کوئری‌ها با PDO prepared statement (prepare واقعی، نه شبیه‌سازی‌شده) و نام جدول/ستون با فهرست سفید. |
| فایل آپلودی مخرب | تشخیص نوع واقعی از روی بایت‌های فایل (نه پسوند)، محدودیت حجم/پیکسل/ابعاد، بازکدگذاری به PNG، رد WebP متحرک، محافظت حافظه. |
| ورود غیرمجاز به پنل | `password_hash`، قفل حساب پس از تلاش‌های ناموفق، محدودیت نرخ بر اساس IP، بازتولید شناسه‌ی نشست، کوکی `HttpOnly` + `SameSite=Strict` + `Secure`، انقضای نشست، نقش‌ها (superadmin/admin/operator/viewer). |
| CSRF / XSS / Clickjacking | توکن CSRF روی همه‌ی فرم‌ها؛ خروجی‌ها escape می‌شوند؛ CSP بدون اسکریپت درون‌خطی؛ `X-Frame-Options`/`frame-ancestors 'none'`؛ `nosniff`؛ `Referrer-Policy`. |
| سوءاستفاده از ربات | محدودیت نرخ پیام هر کاربر، سهمیه‌ی روزانه، سقف کارهای در صف، سقف تعداد پک، مسدودسازی کاربر، حالت تعمیر. |
| دسترسی به خروجی کاربر دیگر | هر دکمه‌ی شیشه‌ای و هر لینک دانلود مالکیت پروژه/کار/فایل را دوباره بررسی می‌کند. |
| ثبت تغییرات | همه‌ی تغییرات پنل در `audit_logs` (کاربر، عمل، هدف، IP) ثبت می‌شود. |

## توصیه‌ها برای راه‌اندازی

* پوشه‌ی پروژه را بیرون از `public_html` بگذارید و فقط `public/` را به دامنه/زیردامنه وصل کنید
  (در cPanel: Document Root زیردامنه = `.../emoji-maker/public`).
* HTTPS معتبر (AutoSSL / Let's Encrypt) برای وبهوک الزامی است.
* مجوز فایل‌ها: پوشه‌ها `750`، فایل‌ها `640`، `.env` فقط `600`.
* پس از نصب، نصب‌کننده‌ی وب خودکار قفل می‌شود (`storage/installed.lock`)؛ می‌توانید پوشه‌ی
  `public/install` را هم پاک کنید.
* `APP_KEY` را عوض نکنید (تنظیمات رمزنگاری‌شده و لینک‌های دانلود به آن وابسته‌اند)؛ از `.env`
  نسخه‌ی پشتیبان امن داشته باشید.
